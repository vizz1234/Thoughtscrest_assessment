1. Executive Summary & Problem Statement

Traditional retail banking chatbots are limited to static monthly account statements and passive one-way transaction notifications. Customers see what they spent after the fact, but receive no autonomous reasoning across historical patterns, no root-cause categorization of spending surges, and no quantified guidance tied to their life goals.

The CrestBank AI Personal Finance Advisor upgrades this legacy experience into an autonomous, multi-agent financial advisory system built on LangGraph and Google Gemini. It coordinates four specialized agents that read multi-month transaction histories, detect behavioral anomalies and subscription creep, enforce strict inter-agent data dependencies, persist customer preferences in Dual-Tier Memory, and block off-topic requests via a Dual-Mode Domain Guardrail.

Mandatory Architectural Dependency Satisfied: The system enforces at both the LangGraph StateGraph edge level and runtime validation level that the Recommendation Agent strictly receives its analytical input (SpendingAnalysisReport) directly from the Spending Analysis Agent.

3. Detailed Specification of the 4 Specialized Agents

1. Planner Agent src/agents/planner_agent.py

Role: Front-door supervisor, guardrail gatekeeper, execution planner, and final response synthesizer.

  • Entry Node (planner_plan_node): Runs the Dual-Mode Guardrail, extracts new user facts/budget updates into Long-Term Memory, classifies intent, and outputs a typed ExecutionPlan.
  • Dependency Enforcement: Whenever recommendations are needed, forces run_spending_agent = True first.
  • Synthesis Node (planner_synthesize_node): Collates outputs from all executed sub-agents into markdown tables and bulleted action plans.
2. Spending Analysis Agent src/agents/spending_agent.py

Role: Transaction data scientist & behavioral pattern recognizer.

  • Tools Called: tool_aggregate_spending_by_category and tool_detect_subscriptions_and_habits.
  • Capabilities: Categorizes 3 months of transactions across 8 categories, calculates MoM dollar/percentage shifts, detects overlapping subscriptions (e.g., 3 video streaming services), and quantifies high-frequency micro-spend habits (e.g., 11x monthly food delivery orders).
  • Output Contract: SpendingAnalysisReport written to state["spending_report"].
3. Recommendation Agent src/agents/recommendation_agent.py

Role: Personalized financial strategist & budget optimizer.

  • Strict Input Contract: Consumes SpendingAnalysisReport directly from the Spending Analysis Agent (raises ValueError if missing).
  • Tools Called: tool_simulate_budget_optimization.
  • Capabilities: Computes monthly/annual savings from right-sizing micro-spend habits, consolidating redundant subscriptions (while respecting LTM constraints like keeping Adobe/Figma), normalizing category spikes, and sweeping idle checking cash into a 4.50% APY vault.
4. Alerting Agent src/agents/alerting_agent.py

Role: Proactive & reactive overspending and risk monitor.

  • Dual Modes: Runs proactively when a customer opens the chatbot (upgrading passive bank notifications) and reactively as a node inside the LangGraph workflow.
  • Tools Called: tool_evaluate_financial_alerts.
  • Signals Flagged: Category budget breaches (≥100% Critical, ≥85% Warning), statistical single-transaction outliers ($Z$-score ≥ 2.2), subscription creep, and low checking liquidity burn risks.

5. Dual-Mode Domain Guardrails & Safety Architecture (src/tools/guardrail_tools.py)

Because a banking advisor must never hallucinate medical, culinary, or off-topic advice—or waste compute running financial database tools on irrelevant prompts—the system enforces a Dual-Mode Domain Guardrail inside the Planner Agent's Entry Node (planner_plan_node) before any sub-agent is invoked:

Mode 1: Live LLM Semantic Intent Guardrail When GOOGLE_API_KEY Is Set

Mechanism: Invokes Google Gemini (temperature=0.0) as a zero-shot semantic compliance classifier before planning.

  • Classification Contract: Returns strictly ALLOW | <reason> or BLOCK | <off-topic category & reason>.
  • Scope Enforced: Permits personal finance, spending analysis, budgeting, savings goals, subscriptions, and account inquiries; blocks all non-financial intents and adversarial prompt injections.
Mode 2: Deterministic Pattern & Scope Guardrail Offline / No API Key

Mechanism: Two-stage deterministic rule engine ensuring 100% protection even without an external LLM key:

  • Stage A — Categorized Off-Topic Regex Blocklist: Blocks Cooking & Recipes (e.g., "give me a pasta receipe"), Medical & Health (e.g., "how to treat my acne"), Coding/Homework, General Trivia/Weather, and Prompt Injection / Jailbreaks.
  • Stage B — Positive Financial Keyword Verification: Rejects queries lacking any banking, spending, budget, or transaction terminology.
LangGraph Short-Circuit Routing on Guardrail Block: When evaluate_domain_guardrail() returns is_allowed = False, the Planner sets user_intent = "BLOCKED_OFF_TOPIC" and route_after_planner() routes directly from planner_plan_node → planner_synthesize_node. Zero sub-agents (Spending Analysis, Recommendation, Alerting) or SQLite transaction tools are executed, and the blocked event is logged as a [GUARDRAIL] step in logs/.

7. Key Architectural Decisions & Engineering Trade-Offs

Architectural Decision Why Chosen (Pros) Trade-Offs Mitigated
ADR-01: LangGraph StateGraph vs. Peer-to-Peer Swarm Guarantees deterministic execution order and enforces via conditional edges that Recommendation Agent always receives state["spending_report"] from Spending Analysis Agent. Requires explicit state schema definition upfront, trading free-form agent chatter for 100% banking auditability and zero infinite loops.
ADR-02: Deterministic Python Tool Math vs. LLM Token Math Eliminates LLM arithmetic hallucinations. Every dollar sum, MoM %, $Z$-score, and compound savings projection is 100% exact and executes in <2ms. Requires dedicated Python tool functions in src/tools/ rather than dumping raw transaction CSVs into prompts.
ADR-03: Typed Pydantic V2 Inter-Agent Contracts Prevents "telephone-game" context drift between agents; validates field types at runtime. Schema updates require modifying src/schemas/models.py.
ADR-04: Dual-Mode Gemini Engine + Offline Fallback Supports live Google Gemini when GOOGLE_API_KEY is set, while guaranteeing 100% offline execution for evaluators without an API key. Maintains both LLM prompts and structured synthesis templates.
ADR-05: Background File Trace Logging (logs/) Keeps the customer-facing Streamlit UI clean while recording full step-by-step agent traces to logs/agent_traces.jsonl and logs/<CUST_ID>_traces.log. Developers inspect trace logs in logs/ or via python cli.py --demo rather than cluttering the end-user chat bubble.
ADR-06: Dual-Mode Domain & Safety Guardrail Prevents off-topic queries (recipes, medical/acne advice, coding, trivia) and prompt injections using Gemini intent classification when online and deterministic regex + domain-keyword rules when offline. Short-circuits LangGraph directly to refusal synthesis, saving compute and protecting bank compliance boundaries.
